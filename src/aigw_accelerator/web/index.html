TIER MECHANISM

Daily allowance ladder

A / 02

A daily raise moves a principal to a higher configured group override when daily remaining capacity falls below the trigger and monthly spend is still under cap. The next tier is the first rung at or above current daily spend plus one-fifteenth of the monthly cap.

RAISE FLOORdaily spend + monthly cap / 15
EXAMPLE GROUP MOVE · NO ACTION TAKEN
daily-tier-current→daily-tier-next

SCIM adds the target tier group first, then removes the old configured tier group. No group membership is changed by this preview.

Signal caveat — daily spend shown from public system tables is estimated and may lag. It is not the native Gateway enforcement counter or a hard-stop signal.

POLICY & DATA SOURCES

03EXPLICIT ABOUT
WHAT IS ENFORCED.

          

          

            
01
MONTHLY · NATIVE
Account Budget API
The accelerator manages Unity AI Gateway monthly thresholds, group overrides, alerts, and optional usage blocking through the documented account budget interface.
  • Monthly shared and per-user thresholds
  • Declarative reconcile with fetch/modify/write
  • Existing alert and scope protections
SUPPORTED BASELINE

            
02
DAILY · TIERED POLICY
Configurable group ladder
The daily policy selects a tier from the configured ladder, then moves the user into that tier's account group. The default step uses monthly cap / 15.
  • Tier ladder and group names are customer-configured
  • Membership changes use account SCIM
  • Daily spend estimate uses public system tables
BEST-EFFORT TELEMETRY

          

          
PUBLICATION BOUNDARY
The internal console's real-time budget-status RPC and employee/org data are intentionally not included. Daily telemetry is calculated from documented Unity Gateway and billing system tables; because those tables can lag, it must not be presented as the native enforcement counter. The daily tier logic is reusable, but daily period enforcement itself is not created by the standard monthly budget API.
